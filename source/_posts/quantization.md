# 从 $\mathbb{R}$ 到 $\mathbb{Z}$ 的映射
量化的第一步是建立映射关系。我们将 FP16（16位浮点数）映射到 INT4（4位整数），数学上这被称为非对称线性量化。

## 映射公式

线性量化（Linear Quantization）公式，也称为仿射量化（Affine Quantization）。对于原始权重矩阵 $W$，其量化过程为：

$$
W_q = \text{clamp}\left(\text{round}\left(\frac{W}{S} + Z\right), q_{\min}, q_{\max}\right)
$$

1. **缩放与偏移**：$\frac{W}{S} + Z$

- $W$ (Original Weights)：原始的浮点权重矩阵。
- $S$ (Scale， 缩放因子)：它是一个浮点数，定义了原始值和量化值之间的比例关系。
- $Z$ (Zero-point)：这是一个整数，代表原始浮点数中的 0 在量化后的整数空间中对应的值，解决了数据分布不对称的问题。
  - 引入 $Z$ 是为了处理非对称分布。例如，如果你的权重分布在 $[-1, 5]$，通过 $Z$ 可以让浮点 0 准确地映射到一个整数，这对于 Padding（补零）等操作至关重要。

**注释：Padding操作的影响**

假设我们对特征图补零，量化以后依然补零，那么我们要保证量化后的零就等于量化前的零，通过 $Z$ 偏移来解决（当然也带来了**数值映射密度不均**的问题）
```
0 0 0 0 0
0 1 2 3 0
0 4 5 6 0
0 7 8 9 0
0 0 0 0 0
```

2. **离散化**：$\text{round}(\cdot)$
将缩放和平移后的浮点数取整，这是丢失信息的关键一步。由于浮点数是连续的，而整数是离散的，取整操作会带来**量化误差（Quantization Error）**。

3. **边界限制**：$\text{clamp}(\dots, q_{\min}, q_{\max})$
截断超出范围的值，该操作也会带来**量化误差**

反量化（推理时还原）为：

$$
\hat{W} = S \cdot (W_q - Z)
$$

# 算法演进

## 算法总览

| 量化方法 | 典型算法 | 定义 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| 训练后量化<br>Post-Training Quantization (PTQ) | GPTQ、SmoothQuant、GGUF (K-Quants) | 在模型训练完成后对权重与激活直接量化，无需再训练 | 实现简单、速度快、成本低，无需额外标注数据 | 精度损失相对较大 | 快速部署、资源受限场景 |
| 量化感知训练<br>Quantization-Aware Training (QAT) | AWQ、QLoRA、LSQ | 在训练过程中模拟量化误差，通过反向传播让参数适应低精度表示 | 精度损失小、恢复能力强 | 需额外训练与校准，计算与数据成本高 | 对精度要求高、可接受微调成本的场景 |
| 非均匀量化<br>Non-Uniform Quantization | GPTQ、EXL2 | 量化间隔不固定，根据数据分布自适应划分区间 | 同比特下精度更高，更贴合非均匀分布 | 实现与计算复杂度高 | 数据分布不均、对精度要求极高的模型 |
| 均匀量化<br>Uniform Quantization | 线性/仿射量化、GGUF | 量化间隔固定（等间隔），采用缩放与零点偏移的仿射映射 | 实现简单、计算高效、硬件友好 | 对非均匀分布不够贴合，可能损失精度 | 通用低精度推理、工业界主流方案 |
| 权重聚类<br>Weight Clustering | TensorFlow Clustering、部分剪枝框架 | 将相似权重聚类为少数中心值，用中心值替代原权重 | 进一步压缩参数量与计算量，有损压缩效果好 | 可能影响精度与收敛 | 权重冗余明显、对压缩率要求高的模型 |
| 仅整数量化<br>Integer-Only Quantization | TFLite 整型、ONNX Runtime 整型 | 推理全流程（权重、激活、运算）均使用整数，无浮点运算 | 推理加速、无需 FPU，利于低功耗与边缘部署 | 需校准与整型友好设计，精度与动态范围受限 | 无浮点支持的硬件（如低端 MCU）、对延迟与功耗敏感的场景 |
| 混合量化<br>Hybrid Quantization | 多精度部署（如 vLLM 分层位宽） | 对不同层或不同参数采用不同量化位宽与策略 | 在精度与效率间灵活权衡，可针对敏感层保留高精度 | 需做敏感性分析与调参 | 需在精度与吞吐/时延之间做细粒度权衡的部署 |
| 逐张量 / 逐通道量化<br>Per-Tensor and Per-Channel | GPTQ/AWQ 等均支持 per-channel | **逐张量**：全张量共用一组量化参数；**逐通道**：每个通道独立一组参数 | 逐张量：实现简单、内存与实现开销小；逐通道：精度更高、对通道间分布差异更友好 | 逐张量：精度损失较大；逐通道：存储与计算开销略增 | 逐张量：内存与实现极简场景；逐通道：追求更高精度的主流选择 |
| 自适应量化<br>Adaptive Quantization | PyTorch Dynamic Quantization、运行时动态策略 | 根据输入或运行时状态动态调整量化位宽或策略 | 能适应分布变化，在动态场景下兼顾精度与效率 | 实现复杂，运行时开销与调度难度增加 | 输入分布变化大、难以获得稳定校准数据的场景 |

## GPTQ：利用二阶导数信息

GPTQ 针对LLM，通过寻找一个量化矩阵 $\hat{W}$，使得在给定输入 $X$ 的情况下，量化后的层输出与原始层输出之间的平方误差最小：

$$
\min_{\hat{W}} \|\|WX - \hat{W}X\|\|_2^2
$$

GPTQ 的核心是 **海森矩阵（Hessian Matrix）**。它认为量化一个权重后，可以通过调整该层剩余的权重来“补偿”带来的误差。
**海森矩阵 = 二阶偏导数组成的方阵**，二阶偏导数代表了该方向上的弯曲程度，所以：

- 海森值大 → 权重很敏感，一动 loss 飞 → 不能随便量化
- 海森值小 → 权重不敏感，可以大胆量化 / 剪枝

## AWQ：激活感知的权重量化

**AWQ 发现 LLM 的激活值中存在显著的离群点（Outliers）。**

AWQ 需要用少量校准数据（比如 100 条无标注文本）跑一遍 FP16 精度的原模型，目的是统计每个输出通道的激活特征，拿到每个通道的激活尺度 $s_{X_j}$​​ 后，为每个输出通道计算激活感知缩放因子 $s_j​=(s_{X_j}​​)α$，其中 $α$ 是通过网格搜索得到的最优超参（通常 0.5–1）

**量化前**：对权重做通道缩放 $W_{scaled}​=W \cdot \text{diag}(s)$ 放大关键通道权重，让其在低比特中更易区分、减少舍入误差。
**推理时**：激活除以相同缩放因子做补偿，保证数学等价 $Y = (W_{\text{scaled}} \cdot X_{\text{quant}}) \oslash s$

- **算法思路**：与其费力优化权重映射，不如直接给那些对应大激活值的权重通道“加权（Scaling）”(数值变大了，它在量化过程中保留的有效位就更多了)。通过保护这 $1\%$ 的关键通道，其余 $99\%$ 的权重即便暴力量化，模型整体精度依然稳健。
- **工程优势**：由于不改变权重原本的数据类型分布，推理速度比 GPTQ 快得多。

## SmoothQuant：平滑激活值

在量化大模型时，工业界发现了一个尴尬的现象：

**权重（Weights）**：非常容易量化，分布均匀，即便量化到 8-bit 甚至 4-bit，精度也几乎不掉。

**激活值（Activations）**：极难量化，激活值中存在严重的离群点（Outliers）。

这些离群点在某些通道上比平均值大 100 倍以上。如果对激活值进行 8-bit 量化，为了照顾这些极大的离群点，量化器的步长会变得巨大，导致其他正常的数值全部被“截断”或“归零”，模型精度直接崩盘。

利用线性代数中的等价变换：
$$
Y = X \cdot W = (X \cdot \text{diag}(s)^{-1}) \cdot (\text{diag}(s) \cdot W)
$$

这里，$s$ 是一个平滑因子（Smoothing Factor）。
- 对激活值 $X$：除以 $s$，把那些突出的离群点“压低”，让分布变得平滑。
- 对权重 $W$：乘以 $s$，虽然权重的数值变大了（变得稍微难量化了一点点），但因为权重本身分布很均匀，这点压力它完全承受得住。

# 量化格式

| 格式名称 | 核心算法 | 适用场景 | 特点 |
| --- | --- | --- | --- |
| **GGUF** | 多种线性量化 (K-Quants) | CPU / Apple Silicon / 混合推理 | 极其灵活，支持单文件分发，llama.cpp 的标准格式。 |
| **EXL2** | 基于 GPTQ 的非均匀量化 | NVIDIA GPU 推理 (4090/A100) | 性能巅峰。支持 4.25 bpw 等非整数比特，Kernel 深度优化。 |
| **AWQ** (Safetensors) | 激活感知量化 | 生产级高并发部署 | vLLM、TGI 等主流推理框架原生支持。 |
| **FP8 (E4M3)** | 硬件原生量化 | H100 / RTX 40 系列 | 未来趋势。由硬件直接支持，几乎无精度损耗。 |
